# 异史 · 故事模拟器

一个支持本机服务和纯浏览器运行的中文互动小说模拟器。填写角色名字和一个「假如」，先确认开局条件，再由 OpenAI 兼容模型推演和写作；可选 Gemini 原生联网考据。故事按因果自然收束，**无最低章数、最多 30 章**，每章 **3000～8000 个非空白、非标点文字字符**，关键节点由玩家决定，结局后给出有章节依据的评价。

## 联网考据（默认关闭）

1. 在「模型连接」新增或选择 Gemini 配置：CPAMC Base URL 可用 `https://mofi1994.top/v1`，模型例如 `gemini-3-flash`。沿用业务 API Key；也支持原有管理密钥换取业务凭证方式。
2. 点击「检测联网能力」，返回真实搜索词及有效网页来源才算通过。检测会调用一次模型。
3. 新建模拟时勾选「开启联网考据」，选择「Gemini 考据模型」。确认开局后搜索一次背景，保存笔记及来源供正文使用；正文和生图仍使用各自配置。
4. 已有模拟先暂停，再在「本次模拟的模型」修改开关。尚无考据资料时，下次继续推演会搜索；已有资料不会重复搜索或重写已完成章节。

搜索使用 `/v1beta/models/{model}:generateContent` 和 `tools: [{googleSearch:{}}]`，不依赖 Responses `web_search`。无搜索证据或网络失败会保留检查点并提示重试，也可关闭开关后继续。资料来源在故事的资料面板显示，不能把反事实推演视为已证实史实。纯浏览器模式还要求该原生接口支持 CORS。

## 在线使用（GitHub Pages）

在线地址：<https://zyz9408.github.io/StoryMode/>。无需安装 Python 或 Node.js，打开「模型连接」填写自己的接口和模型即可使用。

- 在线版直接从浏览器请求供应商，接口必须支持 HTTPS 和 CORS；文字、模型列表、管理接口以及图片下载地址都需要允许跨域。应用不提供公共代理。若供应商不允许跨域，请使用本机版。
- 故事、预设和插图保存在当前浏览器的 IndexedDB，不上传 GitHub，不与本机 SQLite 自动同步。清除网站数据会删除故事，请及时导出 Markdown。
- API Key/管理密钥仅保存在当前标签页的 sessionStorage 中，刷新仍可用，结束会话后需要重新填写；此模式不使用 Windows 加密。避免在共用电脑保存会话。
- 生成时需要保持页面打开，刷新或关闭会中断任务，重新打开后从检查点手动继续。一个站点只允许一个标签页操作，避免重复提交。
- 支持原有正文生成、重大决策、终局评价、重写、主角定制、自动生图及预设管理。预设内的扩展脚本不执行。

本地验证纯浏览器版：`npm run build:pages` 后运行 `npm run preview:pages`。

更新部署：先提交并推送源代码，再运行 `npm run publish:pages`。此命令仅把 `dist-pages` 发布到 `gh-pages` 分支，不包含数据库、密钥或个人预设。在 GitHub 仓库 Settings → Pages 中，选择 Deploy from a branch → gh-pages → /(root)。发布结果可在仓库 Actions 的 Pages 构建中查看。

浏览器验收：`npm run test:pages`；本机验收：`npm run check` 和 `npm run test:ui`。

## 趣味结局评分

结局评价包含主角、势力、朋友、对手、时代影响五张评分卡，每项有 0～100 分、趣味称号、点评和章节依据。本次总分由程序按 30%、25%、20%、10%、15% 加权计算；故事未涉及的类别不评分，剩余权重重新归一。S/A/B/C/D 等级对应 90/80/65/50 分界。评分仅作娱乐复盘，不代表客观历史判断。

所有评分统一采用主角视角：主角看目标与最终归宿，势力看治理与传承，朋友看平安与互信，时代影响看长期净成果。对手项由程序按 `100 − 对手自身结局分` 计算：敌人越失势、结局越惨，主角此项越高；朋友牺牲、己方覆灭的代价计入各自项目，不能因悲壮而加分。旧版评分保留并提示重新生成，不直接猜测翻转历史分数。

已有故事可以在「结局评价」点击「生成趣味评分」；新评分可点击「重新生成评分」。该操作只调用模型更新评价，保留正文、世界状态和原评价直到新结果通过检查，导出 Markdown 也包含评分。

## 启动

需要 **Windows、Python 3.10 或更新版本（包含 Tkinter）和 Node.js 24 或更新版本**。

1. 双击 `start.pyw`，在图形启动器中点击「启动模拟器」。也可以执行 `python launcher.py`。首次运行会安装依赖并构建网页，默认自动打开浏览器，不会弹出命令行窗口。
2. 在浏览器打开 <http://127.0.0.1:3210>。
3. 打开「模型连接」，填写配置名称、Base URL、模型和 API Key，保存后测试文字连接。
4. 新建模拟，选择文字与插图配置，填写名字和事件，生成并确认开局。

启动器支持状态检查、启动、停止、打开网页、实时日志与强制重新构建。平时只在源码发生变化时构建。停止自己启动的服务时，会先请求保存检查点；对于已经由其他窗口启动的服务，只连接和打开网页，不擅自停止。原 `start.cmd` 已替换为图形启动入口。

命令行启动：

```powershell
npm install
npm run build
npm start
```

开发模式为 `npm run dev`，浏览器访问 Vite 输出的本机地址（通常是 `http://127.0.0.1:5173`）。本地服务端口默认 3210；生产启动可通过 `PORT` 环境变量修改。开发代理固定连接 3210。

## 连接模型

- **Base URL** 是 API 根地址，例如 `https://供应商地址/v1`，不要附加 `/chat/completions`。程序保留你填写的路径并追加端点。
- 「载入列表」访问 `GET /models`，尚未填写模型名也可载入；不支持列表的供应商可手动填写。
- 文字采用 `POST /chat/completions`。默认开启流式输出；接口不支持时，在配置中关闭流式输出。接口忽略流式参数而直接返回 JSON 也能处理。
- 可保存多组文字和生图配置。章节插图使用独立选择的配置，支持 OpenAI Images 或 Gemini 原生生图。
- API Key 留空会保留已有 Key。对不需要鉴权的本机兼容接口，可以不填写 Key。
- 模型列表、文字连接测试会访问所填的供应商；主题生成、正文生成、审核、修订与生图均可能计费。程序不估算未提供定价的第三方费用。

### CLIProxyAPI 管理前端适配

在「连接方式」选择 **CLIProxyAPI 管理密钥**，可以直接填写 `https://mofi1994.top/management.html`。程序会规范化为对应的 `/v1` 地址，本机版管理密钥由 Windows 当前用户加密保存，浏览器版仅保留在当前标签页会话中。

服务端只读请求同一站点的 `/v0/management/api-keys`，使用返回的第一个非空业务 Key 调用模型。管理密钥不会发送到文字、生图或 Gemini 接口，也不会返回浏览器。业务凭证最多在服务端内存缓存一分钟，程序不修改远程账号或管理配置。切换鉴权类型时需要重新填写对应密钥，避免混用。

管理端若提示无效密钥、禁止远程管理或临时 IP 封禁，程序会明确报错，不自动循环鉴权。管理界面能够打开，不代表管理 API 当前允许访问。

「配置用途」可标记文字或生图，新建模拟时据此预选。模型列表载入后提供可搜索的下拉列表；生图可按名称筛选候选，也可显示全部或手填自定义别名。在新建模拟、修改本次配置和章节配图中，都可以独立载入和选择生图模型，覆盖该配置的默认模型。模型名称筛选仅供选择，不保证模型实际具备生图能力。

### AI 生成模拟主题

新建模拟中点击「AI 生成主题」，可填写方向（例如三国、普通人穿越、有限物资、科技变革），也可留空。使用当前选中的文字模型生成 3～6 个完整模拟事件及现实约束；点击卡片填入事件，再编辑或创建模拟。「换一批主题」会把上一批内容作为去重参考。主题推荐不会自动开始长篇写作，也不伪称已经完成考据。

### 正文与搜索分离

正文仍使用普通 Chat Completions，不注入搜索工具。只有主动点击联网检测或为模拟开启联网考据时，才通过 Gemini 原生接口传递 `googleSearch`；不逐章自动搜索，不把工具列表回显或普通文本当成搜索证据。

旧存档沿用其已保存的开关。关闭联网时跳过搜索阶段；开启时保留搜索检查点、资料及来源，搜索失败不会静默降级。关闭联网不影响模型列表、AI 主题、文字写作或生图等必要 API 调用。

生图支持 OpenAI Images 和 Gemini 原生 `generateContent` 的 `responseModalities: ["TEXT", "IMAGE"]`，自动模式为 Gemini 模型选择原生生图。后者读取 `inlineData` 图片，实际尺寸由模型决定；其他模型使用 Images 请求 1024×1024。

## 主角定制与自动插图

- 新建模拟可填写主角姓名、外形、性格和背景。外形写入生图提示词，性格与背景进入开局、大纲、正文及审核上下文。姓名留空时，穿越沿用玩家名字；历史改写使用事件核心人物，玩家仅署名。
- 填写定制后，开局完成会自动排队生成主角立绘。阅读页「主角定制」可查看立绘、修改设定或重新生成。修改用于未来写作与生图，不会改动已发生的正文。
- **自动章节生图默认开启**：每章审核提交后排队生成一张插图。图片使用独立后台队列，不阻塞下一章写作；刷新仍继续。无生图配置、限流、失败及暂停均显示状态，正文不受影响。立绘和章节图都会产生所选供应商的生图费用。
- 章节图自动加入主角外形、性格、背景和该章人物档案。Gemini 原生模式会同时传入已保存且与当前设定匹配的立绘作为参考图；OpenAI Images 兼容模式使用文字外形约束。模型的跨图一致性仍取决于供应商能力。
- 在「本次模拟模型」中选择生图配置和模型，可关闭自动生图。重新保存配置会暂停原队列，并按新配置补齐缺失图片。旧故事可点击「补齐章节插图」，单章也可编辑提示词后重试。
- 生图任务保存在 SQLite 独立表中，避免覆盖正在推进的文字任务。服务重启后未完成图片保留为暂停，可用「补齐章节插图」或重新生成立绘恢复，已完成图片不会重复生成。页面「暂停」控制正文，图片队列独立执行；停止服务会一并保存并中止图片请求。

## 写作预设

侧栏「写作预设」支持 SillyTavern Chat Completion JSON（`prompts` / `prompt_order`）。实现以本机 SillyTavern `8172dcd0ee672d3cd9a5e5f7af134f91a45cd2b8` 的 PromptManager、OpenAI 消息编排和 regex 引擎为对照。

**添加正则**：打开「写作预设」，选择预设，在「正则脚本」点击「添加正则」，填写查找表达式（例如 `/旧词/g`）和替换内容，然后「保存预设」。可调整顺序、开关和应用范围，并单独导出正则 JSON。导入完整预设时自动读取内嵌正则并显示条数；「导入正则 JSON」也接受完整预设文件，只提取正则到当前预设，不改变提示词。兼容 `extensions.regex_scripts`、顶层 `regex_scripts` / `regexScripts` 及旧嵌套 `extensions.extensions.regex_scripts`。已保存的旧格式数据在读取时自动适配；手动清空的正则列表不会从旧扩展元数据中重新恢复。

**DeepSeek / HTTP 422**：负数 `seed` 是酒馆的随机种子哨兵值，发送时省略。连接 `api.deepseek.com` 或使用 `deepseek-chat` / `deepseek-reasoner` / `deepseek-flash` / `deepseek-vN` 名称的兼容接口时，不发送 DeepSeek 未声明的 `seed`、`top_k`、`top_a`、`min_p`、`repetition_penalty`、`verbosity`；OpenRouter 保留其扩展采样参数。只适配请求，不删除预设原值或正则。预览显示过滤说明。400/422 错误展示经脱敏、限长的字段诊断，不再只有状态码，也不会自动修改参数并重试。可在预设编辑器修改「最大输出 tokens」或清空以采用供应商默认值；不同模型和中转服务的限制以其错误说明为准，不统一把所有 DeepSeek 模型强制限为 8192。参考 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。

- `system`、`user`、`assistant` 条目直接成为请求里的消息，不再嵌入 `creativePreset`。保留编排开关、深度、优先级、触发类型及禁止覆盖设置；同深度的优先级和角色分组按参考版本处理。
- 导入后选择预设并启用。预设用于正文，以及携带故事预设的 JSON 任务；JSON 任务使用 `quiet` 触发类型，并在末尾添加结构化输出控制消息。连接测试、主题推荐、生图和独立联网接口不携带故事预设。
- 角色、性格、情景、世界信息和历史占位由 StoryMode 上下文填充。已有章节作为 assistant 历史，玩家决策作为 user 历史。当前任务作为 user 消息；没有启用 `chatHistory` 的简化预设会在末尾附加历史及任务，预览会提示这个适配行为。
- 支持嵌套的用户、角色、描述、情景、最后消息等宏；局部与全局变量的 set/get/add/inc/dec/has/delete/flush；注释、trim、newline、space、random、基础骰子和日期时间。局部变量随故事保存，全局变量在本应用各故事间共享。未知宏保留原文并列在预览中，不再静默删除。预览和显示正则使用变量副本，不更改存档变量。
- 导入预设中的 `extensions.regex_scripts`，也可独立导入单条或数组格式正则。编辑器支持排序、开关、替换内容、捕获裁剪、查找宏转义、深度和应用范围。`$0` / `{{match}}`、编号和命名捕获遵循酒馆规则。普通 AI 输出替换在生成完成后写入正文；`promptOnly` 只改变发送的历史，`markdownOnly` 只改变阅读显示。不会把显示过滤后的文本写回正文或用于审核。跨流式块的匹配会在完整文本上处理，启用普通输出正则时文本在完成后统一显示。
- 采样参数默认随新导入预设开启，包括温度、top_p、惩罚、top_k/min_p 等，以及 `openai_max_tokens` 对应的 `max_tokens`、seed、stop、reasoning_effort、verbosity；供应商必须支持所选参数，可在编辑器关闭参数应用。连接地址、模型和 API Key 仍取自模型连接设置。
- 移除了原有的 48,000 字符静默跳过预算。导出同时包含酒馆的 `prompts`、`prompt_order`、`extensions.regex_scripts` 和本应用编辑字段，保留其他编排及扩展数据。保存并预览可查看消息角色、内容、解析诊断和完整请求 JSON（不含鉴权）。预览使用正文任务模板；实际生成还会加入当时的章号、场景和修订条件。

兼容边界：这不是整个 SillyTavern 运行时。酒馆助手 / SPreset / STscript / JavaScript 扩展仅保留数据，不执行；世界书关键词激活、全部新宏语法、模型专用 tokenizer 的上下文裁剪、供应商专用消息后处理和原生 Claude/Gemini 文字发送协议尚未移植。当前文字请求使用现有 OpenAI-compatible `chat/completions` 通道，HTML 替换结果仍作为文本显示，不运行网页。不能把此实现称为与所有酒馆扩展和供应商 100% 等价。UI 中会提示未知宏、无效正则及上下文裁剪差异。

验证：`npm test` 包含消息编排、正则、参数、变量持久化、导出再导入、流式跨块和 API 测试。设置 `SILLYTAVERN_REFERENCE` 为酒馆源码目录，可额外运行直接调用该版本 regex 引擎与深度编排函数的差分测试；本机默认检查 `E:/SillyTavern-Launcher/SillyTavern`。测试仅读取源码，不连接模型、不复制用户预设入仓库。本地 UI 与 Pages 测试需串行运行（它们共用模拟供应商端口 3213）；未安装 Playwright 浏览器时可设置 `PLAYWRIGHT_CHANNEL=msedge` 使用已安装的 Edge。

## 生成与阅读

1. **开局解析**：识别穿越、历史改写等类型，提出可编辑的年代、地点、身份、目标、资源和假设。穿越使用玩家角色；历史改写以历史人物为中心。
2. **世界设定与大纲**：由模型分析背景与现实约束，建立人物认知、资源、关系、势力和冲突。大纲根据故事需要安排 1～30 章，允许提前自然完结；只标记重大分歧候选，不强制出现决策。
3. **分章写作**：每章一次流式生成完整正文，再一次审核，减少场景规划与逐段等待。目标 3500～4500 字，仍严格检查 3000～8000 字范围。日常琐事略写，允许时间跳跃，每章必须推进主线并产生实质结果。上下文包含有界的已有历史资料、历史摘要、当前世界状态和近期正文，而非整本小说全文。
4. **审核与提交**：检查篇幅、情节变化和连续性。程序独立校验时间不能倒退、资源单位不能突变。资源余额由程序按原余额加本章流水计算，金银等小数用十进制相加，避免模型重复算余额或浮点尾差造成误报。缺失流水、超支等问题单独核对账本，最多两次，期间不重写正文；仍失败则保留草稿与原余额供重试。模型审核负责人物动机、知识边界、因果和冗余叙述。最多自动修订两次，仍不通过就停止，保留草稿。
5. **玩家决策**：只在改变核心目标、阵营归属、关键人物生死或重大不可逆代价的分歧前给出 2～4 个方向，也能输入自由行动或交给角色判断。全书至多 3 次、彼此至少隔 4 章，没有最低次数。日常事务由角色自行处理。提交前不会生成下一章。选择只影响尚未发生的剧情，不回滚旧章节。
6. **动态结局**：每章更新剩余大纲；任何章节都可在终局完整时结束，不为凑足 15 章拖延，第 25 章起收束，第 30 章必须完成终局。终章采用总结性质的后传：跨时间写到主角死亡、重要人物归宿、组织与政权最终命运、时代落幕及同时代和后人评价，不以受封、战役胜利或新的征程代替完结。审核必须逐项提供正文依据；引文未匹配时，额外从正文按段号选择证据并由程序截取原文，避免模型改写引用造成误报。正文确实缺项时优先定向补写后传，再完整审核资源和因果；仍不完整则保留草稿。若最后一章未通过收束审核，将停止并允许修订，绝不把未完成故事强标为完结。
7. **评价与插图**：完成后评价目标、决策、资源、可行性、长期影响和不确定性，引用实际章号。每章完成后默认自动排队生图，也可以编辑提示词手动重试。

阅读页向下滚动即可连续读到后续章节，新完成的章节自动接在末尾，目录高亮跟随阅读位置；也支持章节切换、字号、明暗主题、实时草稿、世界状态、已有资料、选择记录和 Markdown 导出。世界面板显示**最新已完成章节**的状态，可能包含后续剧情。草稿尚未通过审核，不计入正式故事。

自动检测能约束篇幅和状态一致性，不能保证文笔或史学结论准确。模型背景知识可能存在局限；反事实结局是带有假设的模拟，不是历史必然。测试供应商只验证程序流程，不构成文学质量示例。

## 重写章节与删除

已到结局的故事可点击「补全终局」，在保留既有事件的基础上重写最后一章并推进到人生与时代落幕，不增加章数。通过审核后事务更新末章和世界状态，再重新生成评价；终局审核通过前，失败、暂停或取消会保留原结尾，评价生成失败可继续重试评价。

- 每个已完成章节顶部都有「重新生成本章」。确认后从该章重新推演：保留此前章节，删除本章及全部后续章节、相关插图、后续决策与结局评分；此操作不可撤销。
- 世界状态恢复到所选章节开始前的检查点，资源从当时余额继续核算，后续大纲仅依据保留前文与改写要求重新规划。缺少可恢复的检查点时会拒绝操作，保留故事。
- 重新推演自动继续，遇到重大决策等待重新选择。可暂停、刷新或重启后从检查点恢复；新章节逐章审核提交并按原设置自动生图，完结后重新评分。
- 书架每本书可点击「删除」，确认后先停止后台任务，再删除该故事的章节、草稿、评价和全部插图。此操作不可撤销；其他故事与模型连接不受影响。删除时会一并取消该故事排队和正在生成的插图。

## 暂停、断线和数据

- 关闭或刷新网页不会停止后台任务。点击「暂停」才会取消当前请求；草稿和旧版已完成场景会保存。
- 整章生成中断后重新生成该章，中断片段不会拼接进正式正文；旧版本已完成场景会作为事实传入并整合。修订过程中中断会保留上一版完整草稿。整章写作请求允许最多 10 分钟，随时可以主动暂停。
- 服务重启后，原本在运行的任务变为「已暂停」，需手动继续，避免自动产生费用。已完成章节不会重复提交。
- 每章与它的世界状态在同一个 SQLite 事务中提交；章节编号有唯一约束。等待决策时也会持久化当前问题。
- 保存位置为项目下 `data/storymode.sqlite`，插图为 `data/images/`。备份时先停止服务，再复制整个 `data` 目录。不要只复制运行中的 SQLite 主文件而遗漏 WAL。
- API Key 由 Windows DPAPI `CurrentUser` 加密；密钥只在本机服务端解密，列表、错误提示和故事导出不返回 Key。将数据库复制到其他 Windows 用户后需要重新填写 Key。
- 服务只监听 `127.0.0.1`，不提供账号或云同步。移动端布局可在本机浏览器的设备模拟器查看；默认不向局域网开放。

## 代码结构与接口

- `src/`：React 中文界面与响应式阅读样式。
- `server/app.mjs`：Fastify API、SSE、导出与静态资源。
- `server/engine.mjs`：持久化生成状态机；`provider.mjs`：文字与插图适配；`store.mjs`：SQLite 与加密配置；`schema.mjs`：结构验证及资源核算。
- `test/`：HTTP 模拟供应商、后端测试和浏览器测试。

主要接口（写请求需要 `Content-Type: application/json` 和 `X-StoryMode: 1`）：

| 方法与路径 | 用途 |
| --- | --- |
| `GET/POST /api/profiles` | 列出脱敏配置 / 保存配置 |
| `POST /api/profiles/:id/models` | 读取供应商模型列表 |
| `POST /api/profiles/:id/test` | `{kind: "text"}` 文字检测；`{kind: "research"}` Gemini 原生搜索证据检测 |
| `GET /api/presets` | 本地预设库 |
| `POST /api/presets/import` | `{source, filename}` 导入 JSON 文本 |
| `POST /api/presets/:id` | 保存条目开关、内容、顺序和采样选项 |
| `POST /api/presets/:id/preview` | `{storyId?, task?, json?}` 预览消息、参数和兼容诊断 |
| `POST /api/presets/:id/regex/import` | `{source}` 导入独立正则 JSON |
| `GET /api/presets/:id/export` | 导出兼容 SillyTavern 与本应用的预设 JSON |
| `POST /api/stories/:id/preset` | `{presetId, presetEnabled}` 选择、启用或停用预设 |
| `GET/POST /api/stories` | 书架 / 新建模拟 |
| `POST /api/topics` | `{profileId, direction?, previous?}` AI 生成模拟主题 |
| `GET /api/stories/:id` | 章节、状态、草稿和评价 |
| `POST /api/stories/:id/confirm` | 确认编辑后的开局 |
| `POST /api/stories/:id/pause`、`resume` | 暂停 / 恢复 |
| `POST /api/stories/:id/config` | 空闲时更换模型绑定 |
| `POST /api/stories/:id/offline` | `{confirm: true}` 关闭主动联网；保留已有资料 |
| `POST /api/stories/:id/decision` | `{chapter, choice}` 提交当前决策 |
| `POST /api/stories/:id/protagonist` | `{name, appearance, personality, background, generatePortrait?}` 保存主角，按需排队立绘 |
| `POST /api/stories/:id/portrait` | `{prompt?, model?}` 排队生成或重试立绘 |
| `POST /api/stories/:id/illustrations/retry` | 补齐缺失章节插图，包括失败与暂停的任务 |
| `POST /api/stories/:id/chapters/:number/image` | `{prompt, model?}` 选择模型并本地保存插图 |
| `POST /api/stories/:id/chapters/:number/regenerate` | `{instruction?}` 从本章重新推演，清除本章及后续内容 |
| `POST /api/stories/:id/complete-ending` | `{instruction?}` 补全已完成故事的终局并更新评价 |
| `POST /api/stories/:id/cancel-rewrite` | 取消补全终局或旧版重写任务，保留原文；不适用于已确认的重新推演 |
| `POST /api/stories/:id/delete` | `{confirm:true}` 删除故事及插图 |
| `GET /api/stories/:id/events` | SSE 进度、正文片段与章节完成事件 |
| `GET /api/stories/:id/export` | 导出已完成章节、决策、评价与来源 |

协议参考：[Node.js SQLite](https://nodejs.org/api/sqlite.html)、[Fastify](https://fastify.dev/docs/latest/Reference/Server/)。

模型描述兼容：`scenes`、`issues`、`decision.options` 以及世界状态中的 `relationships`、`factions`、`conflicts` 统一支持字符串、对象和嵌套描述。对象会按字段保留信息并转成可读字符串；空对象仍拒绝，资源数量、时间和资源流水继续严格校验。
